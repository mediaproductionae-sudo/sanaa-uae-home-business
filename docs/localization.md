# العربية والإنجليزية — نظام اللغة في صَنْعة

## التنفيذ

العربية افتراضية. زر `العربية | English` موجود في شريط التنقل المشترك للجمهور والبائع والإدارة ومدخل Node. لا تتغير المسارات ولا يعاد تحميل الموقع الثابت عند تبديل اللغة، لذلك تبقى حالات React ومدخلات النماذج والسلة موجودة. الاختيار مستقل في `sanaa-ui-language` وCookie باسم `sanaa-language`؛ لا يعاد استخدام مفتاح بيانات الأعمال أو تغيير الأدوار.

- `components/language.tsx`: مزود اللغة والزر وعزل نص المحتوى.
- `lib/i18n/en.json` و`translate.ts`: ترجمة يدوية صريحة لنصوص الواجهة، وليست ترجمة آلية للنصوص التي يضيفها البائع.
- `lib/i18n/content.ts`: اختيار ترجمة معتمدة للحقل، ثم الأصل عند غيابها، وبناء نص البحث من الأصل والترجمات المعتمدة.
- `components/translation-editor.tsx`: لغة الأصل وترجمة ثانية اختيارية، مع موافقة صريحة على العرض وحالة الاكتمال. يمكن أن يكون المنتج الأصلي إنجليزياً ويملك ترجمة عربية.
- `staging/lib/language.ts`: قراءة لغة الطلب من Cookie على الخادم، دون متغير لغة عام مشترك بين المستخدمين.
- `staging/components/translations.tsx`: حقول الترجمة في محرر قاعدة البيانات.

التبديل يغير `html.lang` و`html.dir`. الصور والشعار والأرقام لا تُعكس؛ تغير اتجاه الأسهم الاتجاهية فقط. الأسماء والأوصاف تستخدم عزل bidi ولغة المحتوى الفعلية. الخط العربي الحالي محفوظ، والإنجليزية تستخدم Arial/Helvetica مع بديل عربي. زر اللغة لا يقل عن 44px للمس.

## البيانات

الاسم والوصف الحاليان هما الأصل؛ `originalLanguage` يحدد لغتهما. تحفظ `translations.ar` و`translations.en` الاسم والوصف و`approved`. لا يمنع غياب الترجمة أو نقص أحد حقولها نشر الأصل. الموافقة هنا مراجعة صاحب المحتوى للترجمة، ولا تعني ترخيصاً حكومياً أو اعتماداً إدارياً جديداً.

تظل المعرفات والحالات الداخلية والفلاتر ومفاتيح localStorage القديمة كما هي. تعرض قيم الخيارات مترجمة، بينما `value` تبقى ثابتة لتجنب تغيير شروط البحث أو حالات الطلبات. أسماء الطلبات التاريخية تبقى لقطات أصلية؛ لا يعاد تحريرها عند تحديث ترجمة الكتالوج.

## Supabase

المهاجرة: `supabase/migrations/202611180005_localization.sql`.

تضيف `original_language` للمتجر والمنتج، وجدولي `store_translations` و`product_translations`. لكل ترجمة سجل مرتبط بالعنصر الأساسي وقيد فريد على العنصر واللغة؛ لا ينشأ متجر أو منتج جديد بسبب اللغة. تبقى أسماء أعمدة `name_ar` التاريخية للتوافق؛ في المنتجات تحمل الأصل وتحدد `original_language` لغته، دون إعادة تسمية الأعمدة التي تعتمد عليها المراحل السابقة.

القراءة العامة تقتصر على ترجمة معتمدة لعنصر ظاهر للجمهور. يستطيع المالك قراءة مسوداته، وتطبق صلاحية catalog.manage للإدارة. الكتابة المباشرة ممنوعة؛ RPCs الجديدة تتحقق من العضو المؤكد وملكية المتجر وتكتب الأصل والترجمة داخل معاملة واحدة. خطأ الترجمة يعيد المعاملة كلها. يسجل التغيير في سجل العمليات.

لم تُعدّل سياسات RLS أو صلاحيات الجداول الموجودة أو العمليات المالية. أضيفت سياسات مستقلة للجدولين الجديدين. يبقى الاعتماد على JWT وauth.uid على الخادم، وليس لغة الواجهة أو حقول المتصفح.

البحث متاح بالعربية والإنجليزية في واجهة السوق، ويشمل الأصل والترجمات المعتمدة وأسماء المتاجر. RPC البحث في Node يحترم الظهور العام والتصفية ومؤشر الصفحة ويعيد 25 معرفاً كحد للصفحة/lookahead، دون تكرار العناصر. لا تُبحث المسودات الخاصة عبر عميل الجمهور.

**طبقت المهاجرة على PostgreSQL محلي معزول بلا شبكة فقط. لم تطبق على مشروع Supabase مستضاف.** يتطلب تشغيل كود Node المتصل تطبيق المهاجرات بالترتيب على بيئة مستقلة ومراجعة النتائج قبل الإنتاج.

## البريد والإشعارات

قالبا تأكيد البريد والاستعادة موجودان في `supabase/templates/`. يختاران لغة الحساب من metadata.ui_language ويستخدمان روابط token_hash المتوافقة مع بوابة Auth الحالية. يجب تثبيتهما في إعدادات Supabase Auth وضبط Site URL وSMTP فعلياً. التسجيل يرفق اللغة المختارة. تغيير اللغة في مدخل Node لحساب مؤكد يحاول تحديث ui_language عبر مسار خادمي محدود؛ لا يسمح بتغيير أي دور من هذا المسار. لا ينتظر تبديل الواجهة نجاح هذه المزامنة؛ الاختيار المحلي يبقى فعالاً.

`lib/i18n/notifications.ts` يوفر قوالب تحديث الطلب باللغتين للربط بخدمة إرسال مستقبلية؛ لا يرسل رسائل ولا ينشئ عمليات شراء أو شحن. الزائر غير المسجل لا يستطيع تعديل لغة رسائل حساب يخص بريداً آخر.

## الاختبارات المنفذة

- TypeScript وبناء الموقع الثابت ومدخل Node: نجحت.
- `tests/localization-content.mjs`: فصل الواجهة عن المحتوى، الرجوع لكل حقل، الترجمة غير المعتمدة، أصل إنجليزي داخل واجهة عربية، ثبات المعرف والسعر.
- `tests/localization.mjs`: اختيار زائر، حفظ نموذج عند التبديل، نشر أصل عربي، عرضه داخل واجهة إنجليزية، إضافة ترجمة لاحقاً، بحث باللغتين، حفظ الاختيار بعد التحديث، ثبات الحساب والسلة والطلبات والأسعار، التنقل بين شاشات العميل والبائع والإدارة.
- اختبارات الرئيسية بالعربية والإنجليزية: تسعة مقاسات لكل لغة، بينها تكبير محاكى وعروض صغيرة وكثافات 1/2/3؛ دون تمرير أفقي أو أخطاء صفحة أو أهداف لمس أصغر من الحد.
- `tests/localization-layout.mjs`: لوحات البائع ومحرر المنتج والإدارة والمستخدمين والملف الشخصي بالإنجليزية على المقاسات السبعة المطلوبة.
- اختبارات الحسابات والبائع وKPIs الإدارة: نجحت؛ عُدّل محدد قديم في اختبار KPI لإثبات النقر بالاسم الفعلي.
- `staging:test:security`: تسع مجموعات حماية محلية نجحت.
- اختبارات قاعدة 4B المحلية: 14 مجموعة نجحت بعد المهاجرة الخامسة، ثم اختبار خاص للترجمات والبحث والعزل والعودة الذرية وصلاحيات المال والسجل.
- `staging/tests/localization.mjs`: لغة Cookie على الخادم، تحديث RSC دون مسح حقول النموذج، عزل جلستين، وحالة Auth غير المربوطة.

هذه اختبارات Chromium بأحجام محاكاة، وليست أجهزة Safari فعلية. SQL اختُبر بمحرك PostgreSQL حقيقي مع عقد Auth/Storage محلي؛ ليس JWT صادراً من Supabase مستضاف.

## حدود التحقق والتشغيل

لا توجد بيانات Supabase أو SMTP مستضافة متاحة. لم تختبر جلسة Auth حقيقية عند تبديل اللغة، ولا إرسال بريد فعلي، ولا PostgREST/Storage عبر JWT فعلي. لا تدل نتائج الواجهة والبناء على نجاح هذه التكاملات. تبقى الوظائف غير المفعلة سابقاً، مثل الدفع والشحن الفعلي والتسويات، غير مفعلة وتعرض رسائل باللغتين.

الموقع الثابت يستخدم اللغة المحفوظة بعد بدء JavaScript؛ HTML/SEO المسبق افتراضه عربي. مدخل Node يقرأ لغة Cookie في SSR. لم تُنشأ مسارات لغات مكررة أو منتجات مكررة لأغراض SEO.
