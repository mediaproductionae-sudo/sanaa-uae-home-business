# المرحلة الثالثة — لوحة الإدارة والحوكمة والثقة

تاريخ المراجعة: 17 نوفمبر 2026، بتوقيت الإمارات.

## النطاق والنسخة المحفوظة

تم تطوير المشروع نفسه باستخدام Next.js App Router والتصدير الثابت. حُفظت حالة المرحلة الثانية في فرع `backup/before-phase3` عند الالتزام `98af6c5`. لم يتغير تخطيط الرئيسية أو صورها أو خطوطها أو ألوانها. التغيير العام مقتصر على ربط ظهور المنتجات والمتاجر بقرارات الإدارة. لم تُضف مكتبات أو قاعدة بيانات أو Supabase أو معاملات مالية.

## الدخول والصفحات

افتح `/admin/dashboard/` واختر «دخول الإدارة التجريبية». يمكن تبديل الحساب التجريبي بين المسؤول ومراجع التراخيص ومسؤول السلامة. هذا اختيار دور محلي واضح وليس مصادقة حقيقية.

| المسار | الوظائف |
| --- | --- |
| `/admin/dashboard/` | عشر بطاقات محسوبة من الحالة المشتركة، ورسوم الإمارات والتصنيفات واتجاه الطلبات |
| `/admin/stores/` | بحث وتصفية وتفاصيل المتجر، مراجعة ورفض وتعليق وإعادة تفعيل مع سبب وتأكيد وسجل |
| `/admin/applications/` | سير انضمام من سبع حالات منفصل عن التفعيل |
| `/admin/licenses/` | مراجعة سبع حالات، نوع الترخيص وإمارته وتواريخه وملاحظات المراجع |
| `/admin/users/` | سجل المستخدمين التجريبيين، تغيير الدور والحالة، حماية آخر مسؤول نشط |
| `/admin/products/` | بحث وتصفية وإخفاء وإظهار مع أسباب وتاريخ قرارات |
| `/admin/orders/` | فترات وتواريخ وتفاصيل الأصناف والأسعار التاريخية وحالات الطلبات وسجل تغيراتها |
| `/admin/complaints/` | النوع والأولوية والمكلّف والحالة والملاحظات وتاريخ الإجراءات |
| `/admin/safety/` | ست فئات بلاغات وثلاث درجات مخاطر ومراجعة بشرية |
| `/admin/categories/` | تفعيل وإيقاف ظهور منتجات التصنيف مع سجل القرار |
| `/admin/reports/` | الإمارات والتصنيفات وحالات الطلبات وأنواع الشكاوى والفترات ومتوسط الإغلاق عند توفره |
| `/admin/audit/` | سجل للقراءة والتصفية والتصدير يعرض قبل القرار وبعده والسبب والمسؤول والوقت |
| `/admin/settings/` | اسم العرض الداخلي وهدف مدة المراجعة، دون تغيير هوية الرئيسية |

## التكامل والبيانات

- مصدر واحد داخل `DemoProvider` يجمع بيانات العميل والبائع والإدارة؛ طبقة القرارات والتحقق في `lib/governance.ts` تمهّد لاستبدال التخزين لاحقاً.
- تعليق المتجر أو حساب البائع وإخفاء المنتج وإيقاف التصنيف ينعكس على القوائم والتفاصيل العامة والتحقق قبل الطلب. تعديل البائع لبيانات متجره لا يمحو قرار الإدارة.
- الترخيص والانضمام والتفعيل حالات مستقلة. جميع إشارات الترخيص تجريبية ولا تمثل اعتماداً حكومياً.
- تحديث الشكوى يظهر للعميل والبائع؛ يستطيع البائع الرد فقط، دون حذف الشكوى أو تعديل قرار الإدارة.
- أسعار الطلب وأسماء أصنافه محفوظة كلقطات تاريخية. لا توجد وظيفة إدارية لتعديل المبلغ؛ تُسجل تغيرات الحالة الجديدة التي يجريها البائع.
- كل قرار مؤثر يحتاج سبباً وتأكيداً. تُسجل القيمة السابقة والجديدة والتاريخ والمسؤول والعنصر. لا توجد أزرار لتعديل السجل أو حذفه.
- ترحيل تلقائي من `sanaa-demo-v2` و`sanaa-demo-v3` إلى `sanaa-demo-v4` مع إبقاء مفاتيح النسخ السابقة وحفظ المفضلة والسلة والطلبات والردود والمنتجات والمتاجر.
- تصدير CSV بترميز UTF-8 وBOM، مع اقتباس الحقول وتحييد بداية الصيغ في البرامج المكتبية.

## الملفات

مضافة:

- `lib/governance.ts`: نموذج الحوكمة والخدمات والتحقق والأدوار والسجل وCSV.
- `components/admin.tsx`: الشاشات الثلاث عشرة والرسوم والجداول والنوافذ والتفاصيل.
- `app/admin.css`: تصميم الإدارة المعزول والمتجاوب.
- `tests/admin.mjs`: التنقل والمقاسات والتكامل وقرارات الإدارة والحفظ والتصدير.
- `tests/admin-extra.mjs`: الصلاحيات والترحيل والتصنيفات وتعليق البائع والإعدادات والتاريخ.
- `docs/phase3.md` و`public/qa/phase3.txt`: هذا التقرير.
- ملفات نتائج JSON داخل `public/qa/phase3/`.

معدّلة:

- `components/demo-state.tsx`: حالة الحوكمة المشتركة والترحيل وخدمات القرار وربط الطلبات والشكاوى.
- `components/demo-page.tsx`: تطبيق الظهور العام وحالة الترخيص المشتركة.
- `app/page.tsx`: فلترة بيانات الظهور فقط؛ لا تغيير في التصميم.
- `app/[...slug]/page.tsx` و`lib/demo-data.ts`: المسارات الثابتة والعناوين.
- `app/layout.tsx`: تحميل CSS الإدارة.
- `components/site-chrome.tsx`: رابط الإدارة في روابط المنصة.
- `package.json`: أوامر الاختبارات الجديدة.
- `tests/seller.mjs`: التحقق من مفتاح ترحيل v4 بدلاً من v3.

## القيود والأعمال المستقبلية

هذه نسخة DEMO ONLY. البيانات محفوظة في المتصفح نفسه؛ لا تتزامن بين الأجهزة أو المستخدمين، وقد تفقد عند مسح بيانات المتصفح. توجد رسالة واضحة عند فشل الحفظ أو امتلاء التخزين.

الأدوار والتحقق محليان وليسا حاجز حماية إنتاجياً. يستطيع من يملك أدوات المتصفح تعديل localStorage، بما فيه سجل العمليات؛ لذلك لا يُعد السجل آمناً أو غير قابل للتلاعب. لا تُستخدم هذه النسخة لجمع بيانات شخصية أو تراخيص حقيقية.

تحتاج المرحلة الرابعة إلى مصادقة خادمية، صلاحيات RLS، قاعدة بيانات مشتركة، تخزين ملفات محمي، تحقق خادمي، سجل تدقيق محمي ونسخ احتياطية. لم يبدأ تنفيذ ذلك هنا. لا مدفوعات ولا شحن ولا تكامل حكومي.

الطلبات والبيانات القديمة التي سبقت إضافة السجل لا تملك تاريخ انتقالات كاملاً؛ تُحفظ حالتها الحالية وتسجل التغييرات الجديدة فقط. زمن معالجة الشكاوى لا يُعرض كرقم مختلق عند غياب تاريخ إغلاق. سجل التفاصيل يعرض البيانات الكاملة أيضاً في قسم قابل للفتح.

اختبارات المتصفح تستخدم Chromium فعلياً مع محاكاة أحجام الشاشة واللمس؛ لا تمثل اختبار أجهزة iPad/iPhone فعلية أو Safari. فحص المساحة الضيقة يحاكي أثر مساحة عرض أصغر، ولا يثبت اختبار قائمة تكبير المتصفح الأصلية.

أجريت الاختبارات على ملفات الإنتاج المصدّرة، لا على نماذج شكلية. في النسخة النهائية نجحت:

مقاسات الإدارة والبائع: 1920×1080، 1440×900، 1366×768، 1024×768، 820×1180، 390×844، 360×800. فُحصت الإدارة أيضاً في مساحة قصيرة 683×384. فُحصت الرئيسية إضافة إلى ذلك على 683×384 و320×600 وبكثافات بكسلات مختلفة. لا تمرير أفقي غير مقصود على مستوى الصفحة؛ الجداول العريضة تملك منطقة تمرير داخلية مقصودة قابلة للتركيز بلوحة المفاتيح. لا يُستخدم تصغير الصفحة عبر transform: scale().

اختبارات الإدارة والبائع والحسابات النهائية لم تسجل أخطاء JavaScript أو Console غير متوقعة. اختبار المعرّف غير الصحيح يتوقع 404 ويختبر العودة إلى المنتجات. نتائج قابلة للمراجعة محفوظة في `/qa/phase3/`، والتقرير في `/qa/phase3.txt`.

## المشكلات التي اكتُشفت وأُصلحت أثناء التنفيذ

- تعارض اسم دالة فلترة الظهور مع متغير محلي سبب خطأ JavaScript في الصفحات العامة؛ أُصلح وأعيد اختبار التفاصيل والقوائم والشراء التجريبي.
- استعادة التخزين كانت تحتاج دمج بيانات الحوكمة نفسها؛ أصبح القرار والسجل محفوظين بعد التحديث مع اختبار ترحيل v2 وv3.
- فصلت حالة الترخيص عن تفعيل المتجر، وربطت عرض الترخيص العام بالمصدر المشترك.
- أضيف التحقق من الصلاحية داخل طبقة القرار، وحماية آخر مسؤول نشط، ومنع تعديل البائع من تجاوز الإخفاء الإداري.
- صُححت مطابقة أعمدة CSV، وأضيف BOM، وأصبح تقرير السنة يجمع 12 شهراً؛ قُيّد ارتفاع الرسم الطويل بتمرير داخلي.
- حُسنت التفاصيل إلى حقول عربية وأصناف طلب تاريخية، مع إبقاء البيانات الكاملة قابلة للفتح وسجل القرارات مرتبطاً بنوع العنصر الصحيح.

لا توجد أخطاء اختبار متبقية معروفة ضمن النطاق المذكور. القيود الإنتاجية والأجهزة غير المختبرة موضحة أعلاه وليست وظائف مكتملة.

## تحديث: تفاصيل بطاقات نظرة عامة

أصبحت البطاقات العشر روابط كاملة قابلة للنقر واللمس والتفعيل بزر Enter، مع الحفاظ على توزيعها ومظهرها وإضافة تمييز عند المرور والتركيز.

- المستخدمون والمتاجر والمنتجات: القوائم الكاملة المقابلة.
- المتاجر النشطة: المتاجر المفعلة التي يسمح قرار الإدارة وحساب مقدم الخدمة بعرضها.
- قيد المراجعة: طلبات الانضمام قيد المراجعة.
- عدد الطلبات وقيمتها: كل الفترات، مع عدد ومجموع مالي محسوبين من الطلبات المعروضة، بما فيها التاريخية.
- الشكاوى المفتوحة: استبعاد جميع الحالات المغلقة.
- البلاغات عالية الخطورة: المخاطر العالية غير المغلقة.
- التراخيص قيد المراجعة: مراجعات الترخيص المطابقة فقط.

تُحفظ الفلاتر الأولية في رابط الوجهة لتعمل بعد التحديث أو فتح الرابط مباشرة، ويمكن مسحها. الملفات المعنية: `components/admin.tsx` و`app/admin.css` و`tests/admin-kpis.mjs` وأمره في `package.json`.

التحقق الفعلي للتحديث: نجح `npm run test:admin-kpis` على 1920×1080 و1024×768 و390×844: البطاقات العشر، تطابق الأعداد والفلاتر، شمول طلب قديم خارج الثلاثين يوماً، مجموع القيمة، Enter واللمس، التحديث والرجوع ومسح الفلاتر، دون أخطاء Console. نجحت إعادة `npm run test:admin` للشاشات الثلاث عشرة على المقاسات السبعة وتكامل قرارات الإدارة، ونجح Build وTypeScript.
