# تقرير الدفعة 4A — صَنْعة | Sanaa UAE

تاريخ التنفيذ: 17 نوفمبر 2026، بتوقيت الإمارات.

## النتيجة والنطاق

أُنجز أساس قاعدة البيانات والصلاحيات والأنواع والتهيئة والوثائق واختبارات PostgreSQL المحلية، ضمن **4A فقط**. لم يبدأ 4B، ولم يُربط Supabase مستضاف، ولم تُرفع المهاجرات أو تُفعّل مصادقة حقيقية أو دفع أو شحن أو تسويات تجارية.

الموقع الحالي والصفحة الرئيسية ولوحتا البائع والإدارة والتدرجات والأيقونات وبيانات المتصفح لم تتغير. `next.config.ts` لا يزال `output:'export'`، وملف استضافة Sites لم يتغير. قوالب التشغيل الديناميكي منفصلة وموسومة بوضوح.

نقطة الرجوع `backup/before-phase4a` تطابق `6dc8589c1bcc1a7106bb34b08c084dc01bd6875a`.

## المخرجات

- **50 جدولاً** بمفاتيح UUID، و**99 علاقة FK**، و**12 enum**، وقيود مبالغ صحيحة بالوحدة الصغرى وتواريخ وحالات وتفرد وفهارس.
- ثلاثة ملفات migrations فعلية، مرتبة بالوقت: أساس الجداول، ثم RLS/الصلاحيات، ثم قيود عدم التعديل والتوازن والتسويات وStorage.
- RLS على كل الجداول العامة، وسياسات قراءة وأعمدة كتابة محددة، مع إغلاق الكتابة المالية وصلاحيات المستخدمين عن المتصفح.
- أدوار Customer/Seller/Admin/License Reviewer/Complaints Officer/Delivery Operator، مع صلاحيات إدارة مفصلة وعزل نطاق البائع والعميل وشركة التوصيل.
- ملفات Storage خاصة وسياسات تمنع الوصول لمستندات متجر آخر وتحد الحجم والأنواع المسموحة.
- Ledger وأحداث مالية وتدقيق غير قابلة للتعديل من التطبيق، وقيود توازن مؤجلة إلى commit، ومنع تكرار مصادر العمولة/أحداث الدفع ومفاتيح الطلبات، والتحقق من تخصيص التسويات الجزئية.
- حفظ سعر الطلب الرئيسي والفرعي وأصنافه ومبلغ payment intent؛ تعديل هذه اللقطات يُرفض حتى من مسار كتابة الخدمة المعتاد.
- أنواع TypeScript مولدة من القاعدة المحلية، وعقود خدمات فقط تحدد مسؤولية الخادم. لا SDK أو service-role client جديد في الواجهة.
- seed مرجعي قابل لإعادة التشغيل، بفئات وشركتين وهميتين غير مفعّلتين وسياسة تخصيص غير مفعّلة؛ لا حسابات أو بيانات مالية.

اختبارات القاعدة تشمل: وجود RLS على كل جدول، عدم الترقية عبر auth metadata، عزل طلبات عميلين، عزل الطلبات الفرعية للبائعين، عدم كشف الطلب الرئيسي للبائع، حماية المسودات والمخزون والمبالغ وحالات الترخيص، منع كتابة أدوار أو تأكيد دفع أو تسوية من المتصفح، عزل التوصيل بحسب التخصيص، عدم كشف الشحنة دون تخصيص، تقييد مراجع الترخيص، عزل مستندات Storage والملاحظات الداخلية، تعليق المستخدم وآخر مسؤول، منع تكرار الطلب/حدث الدفع، علاقة الصنف بالمتجر الصحيح، المبالغ السالبة والمجاميع الخاطئة، عدم تعديل اللقطات والسجلات، تسجيل audit للممثل الفعلي، توازن دفعات ledger، التسويات الجزئية وحد الرصيد، وعدم تكرار عمولة البيع، وفحص grants وتنفيذ الدوال.

هذه اختبارات **PostgreSQL حقيقي**؛ `auth.uid()` وجداول Auth/Storage عقود اختبار محلية وليست تنفيذاً لخدمات Supabase. لم يُختبر signup حقيقي أو JWT توقيعاً أو Auth cookies أو PostgREST/Storage عبر HTTP أو إرسال بريد أو SSR على مضيف ديناميكي. فحص المتصفح Chromium مع محاكاة المقاسات، وليس أجهزة iPhone/iPad فعلية أو Safari.

## حدود الأعمال والأمان المتبقية

المهاجرات تمثل أساساً مراجعاً وقابلاً للاختبار، وليست شهادة جاهزية إنتاجية للمنصة كلها. لا توجد محركات شراء أو تخصيص أو احتساب عمولات أو تأكيد دفع أو استرداد مكتملة في 4A. اختبارات حساب النسب، نجاح/فشل الدفع، الاستردادات التراكمية، السباق على المخزون، انتقالات التشغيل والتسوية، وحسم شركة التوصيل تُنفذ في دفعاتها. لم يُعلن نجاحها هنا.

سياسات RLS الأولية يجب إعادة اختبارها على JWT حقيقي وخدمات Supabase في staging. service_role يتجاوز RLS ويحتاج حدود تفويض خادمية؛ لا يُستخدم من العميل. عقود الخدمة في TypeScript ليست تنفيذ تحقق أو rate limiter. لا توجد حماية خادمية فعلية للواجهات القديمة؛ ما زالت DEMO ONLY واضحة كما كانت.

لا توجد مدفوعات حية أو تحويلات أو API شركات توصيل أو تحقق حكومي. حالة demo_approved لا تمثل ترخيصاً رسمياً. قواعد الأعمال والأهلية والاسترداد والحجز والعكس وإعادة التسوية والإثبات الموثوق لها عقود تصميم موثقة وتحتاج تنفيذ معاملات 4C–4F قبل فتحها.

## المتطلبات التي تحتاج تدخل المالك

فُحصت أسماء متغيرات البيئة المحلية وإعدادات المشروع ومتغيرات Sites التشغيلية؛ لا بيانات Supabase متاحة.

1. اختيار/ربط مشروع **Supabase staging** وتوفير project URL وproject ref والمفتاح العام عبر إعدادات مناسبة.
2. إدخال أسرار الخدمة/قاعدة البيانات فقط عبر مخزن أسرار آمن أو CLI تفاعلي؛ **لا ترسل service_role أو كلمة المرور في المحادثة**.
3. اختيار مضيف Node وstaging domain وredirect URLs وSMTP.
4. مراجعة هذا التقرير والموافقة على **4B**. لن يبدأ الربط أو Auth الحقيقي قبل الموافقة.

الأرقام التجارية وسياسات الضرائب/التقريب/الخصومات والاستردادات وعقود التوصيل والتغطية مطلوبة في دفعاتها. لا تمنع مراجعة 4A، لكنها تمنع اعتماد افتراضات تجارية كاتفاقيات حقيقية.
