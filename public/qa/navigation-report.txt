# تفعيل صفحات صَنْعة والتنقل

## الصفحات

الصفحة الرئيسية `/`، والمتاجر `/stores`، والمنتجات `/products`، والتصنيفات `/categories`، والمفضلة `/favorites`، والسلة `/cart`، وتسجيل الدخول `/login`، وإنشاء الحساب `/register`، والملف الشخصي `/profile`، والطلبات `/orders`، والشكاوى `/complaints`، ولوحة مقدم الخدمة `/seller/dashboard`.

تفاصيل المتاجر `/store/1` إلى `/store/4` وتفاصيل المنتجات `/product/1` إلى `/product/4`. إجمالاً 20 صفحة موجودة فعلياً في تصدير الإنتاج. المعرّفات خارج البيانات التجريبية تُرجع صفحة 404 واضحة بروابط متابعة التصفح.

## الروابط والأزرار

- اكتشف صَنْعة وعرض كل الاختيارات → صفحة المنتجات.
- متاجر من بلادي وبطاقات المتاجر → قائمة المتاجر وصفحة المتجر المطابق.
- صور المنتجات وأسماؤها وأسهم التفاصيل → المنتج بمعرّفه الثابت.
- البحث من الرئيسية → قائمة المنتجات مع نص البحث والإمارة في الرابط. التصنيفات والفلاتر والفرز تعمل على البيانات المشتركة.
- قلب المنتج يضيف أو يحذف المفضلة دون فتح التفاصيل؛ قلب الترويسة يفتح صفحة المفضلة.
- إضافة للسلة، وزيادة الكمية وتقليلها وحذف السطر، ثم إنشاء طلب محاكاة محلي بعد إقرار تجريبي. لا دفع ولا توصيل فعلي.
- ابدأ حكايتك → إنشاء حساب محاكاة. تسجيل الدخول وإنشاء الحساب يتيحان جلسة عرض محلية دون كلمات مرور أو بريد شخصي.
- الملف الشخصي يحفظ اسم عرض وهمياً ويسجل الخروج. الدخول يعيد المستخدم إلى الصفحة المطلوبة عندما تأتي منه.
- الشكاوى تحفظ وصفاً تجريبياً محلياً ويمكن عرضه بعد تحديث الصفحة، دون إرساله لأي متجر أو جهة.
- لوحة مقدم الخدمة تعرض مؤشرات محاكاة وروابط للصفحات؛ زر إدارة المتجر يوضح أن تحرير المتجر والتراخيص غير متاح بعد.
- زر العودة يستخدم سجل المتصفح، مع العودة للرئيسية عند عدم وجود صفحة سابقة.
- قائمة الهاتف تُفتح باللمس والنقر ويمكن إغلاقها بـ Escape، مع إعادة التركيز لزر القائمة. قوائم التصفية Native Select تدعم لوحة المفاتيح.
- حكاية المشروع وشرح الثقة يعملان داخل حوار، وعن التجربة يعرض شرحاً واضحاً. الشعار يعيد للرئيسية من كل صفحة.

## ما اكتُشف وأُصلح

كان المشروع يحتوي على صفحة رئيسية فقط. كثير من الأزرار كانت روابط أقسام أو رسائل تشرح وظائف مستقبلية، ولم توجد ملفات مسارات المتاجر والمنتجات والحسابات. لم يُثبت الاختبار وجود طبقة شفافة تمنع النقر؛ المشكلة الرئيسية كانت غياب الصفحات وروابطها.

فُصلت بيانات المنتجات والمتاجر عن الصفحة الرئيسية، ووُحدت المفضلة والسلة والجلسة والطلبات والشكاوى في مخزن محلي ذي تحقق من البيانات المستعادة، مع ترحيل المفضلة القديمة. عُدلت إعدادات التصدير لتوليد index.html لكل مسار، ما يدعم الفتح المباشر والتحديث في الاستضافة الساكنة. وأُصلح إنشاء معرّف طلب المحاكاة في التشغيل المحلي دون الاعتماد على randomUUID المقيد بالسياق الآمن. تُظهر البيانات غير القابلة للاستعادة أو الحفظ رسالة واضحة.

لم تُغيّر ألوان أو خطوط أو صور أو توزيع أقسام الرئيسية، ولم تُضف مكتبات. استُخدم Next.js الحالي مع Generate Static Params للمعرّفات التجريبية، وأُضيفت أنماط مستقلة للصفحات الجديدة من نفس نظام التصميم.

## الملفات

- app/page.tsx: ربط أزرار الرئيسية بالمسارات والمخزن المشترك.
- app/layout.tsx: مزود بيانات المحاكاة وترويسة وتذييل مشتركان.
- app/[...slug]/page.tsx: توليد الصفحات والمسارات الثابتة وبيانات عناوينها.
- app/not-found.tsx: صفحة خطأ عربية للروابط والمعرّفات غير الموجودة.
- components/site-chrome.tsx: الترويسة والتذييل وروابط الصفحات وقائمة الهاتف.
- components/demo-page.tsx: القوائم والتفاصيل ونماذج وعمليات المحاكاة.
- components/demo-state.tsx: الحالة المشتركة والتحقق والحفظ المحلي.
- lib/demo-data.ts: أربعة منتجات وأربعة متاجر بنفس البيانات والصور السابقة، ومعرّفات مشتركة ثابتة.
- app/globals.css: أنماط الصفحات الجديدة فقط، دون استبدال النظام البصري القائم.
- next.config.ts: trailingSlash للتصدير متعدد الصفحات.
- package.json وtests/: أوامر واختبارات التنقل والتجاوب والحسابات.

## حدود النسخة

المصادقة والأدوار محاكاة محلية؛ ليست نظام أمان إنتاجياً ولا توثيق هوية. البيانات مشتركة داخل المتصفح نفسه ولا تُزامَن بين الأجهزة. الطلبات والشكاوى لا تُرسل للخارج. تحرير المتاجر والمنتجات ورفع التراخيص ومراجعات السلامة المتقدمة غير مكتملة وتعرض توضيحاً عند محاولة استخدامها. لا Supabase ولا معاملات مالية أو بيانات هوية حقيقية.

## نتائج الاختبارات

- نجح بناء الإنتاج Next.js وتوليد 20 صفحة فعلية، ونجح فحص TypeScript.
- اختُبرت الصفحات العشرون مباشرة على خادم HTTP لملفات تصدير الإنتاج، باستخدام Chromium وطلبات موجهة إلى الخادم المحلي: المقاسات 1920×1080 و1440×900 و1366×768 و1024×768 و820×1180 و390×844 و360×800. نجح عرض RTL دون تجاوز أفقي.
- نجحت اختبارات النقر أو اللمس، وحفظ المفضلة والسلة بعد التحديث، والكميات والحذف، وإنشاء طلب محاكاة ثم عرضه بعد التحديث، والبحث والفلاتر والتصنيفات الفارغة، والدخول والعودة للصفحة المقصودة، وتفاصيل المنتجات والمتاجر الأربعة، وزر العودة وسجل المتصفح، ونموذج الشكوى ولوحة مقدم الخدمة.
- نجحت اختبارات إنشاء الحساب وتعديل الاسم وتسجيل الخروج والتحقق من طول المدخلات، وحفظ الشكاوى بعد إعادة التحميل على الكمبيوتر والآيباد والهاتف. وظائف الإدارة غير المتاحة تعرض توضيحاً عند النقر.
- نجح اختبار التجاوب السابق بعد تحديثه لسلوك التفاصيل الجديد في 9 حالات، بما فيها 320×600 ومساحة إعادة تدفق 683×384.
- لم تسجل اختبارات الاستخدام أخطاء JavaScript أو console غير متوقعة. أكدت اختبارات الروابط أن المعرّفات غير المعروفة تُرجع 404 مقصودة مع محتوى عربي مفيد.
- خدمة relay للمعاينة المدمجة لم تعمل في البيئة، لذا استُخدم خادم HTTP محلي مستقل يخدم ملفات الإنتاج، مع متصفح Chromium فعلي. لم تُختبر أجهزة فعلية أو Safari أو مصادقة إنتاجية؛ لا توجد مصادقة إنتاجية في النطاق.

التشغيل: npm run build ثم npm run typecheck ثم npm run test:navigation وnpm run test:accounts وnpm run test:links وnpm run test:responsive. يحتاج الاختبار Chromium مثبتاً أو CHROMIUM_PATH. النتائج واللقطات في work/، وتبقى خارج Git.
